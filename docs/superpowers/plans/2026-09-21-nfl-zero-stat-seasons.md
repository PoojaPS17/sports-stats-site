# NFL seasons with no box-score rows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An NFL regular season that ESPN counts games for (stored in `player_season_stats.games_played`) but for which the database has no regular-season box-score row appears on the player page (season table, career games), with ESPN's games figure and an all-zero stat line, so the site's games figure equals ESPN's.

**Architecture:** `buildProfile` (`src/lib/playerProfile.ts`) builds NFL seasons only from log rows (`bySeason`); the stored games figure (`reportedGames`, loaded by `getReportedGames` in `src/lib/playerLog.ts`) is applied only to seasons that already have rows. Add the missing seasons from `reportedGames`, then make every consumer of a season (season table link, season page, audit) handle them.

**Tech Stack:** Next.js 16 app, TypeScript, `npx tsx --test tests/*.test.ts` (embedded Postgres harness for DB tests), `scripts/audit-player-totals.ts`.

## Global Constraints

- Data accuracy comes first: every figure the site shows must equal ESPN's. Never invent a stat: the only figures for these seasons are ESPN's games played and zero for every stat (verified against ESPN game logs for all 88 known cases, all-zero stat lines). Never lose or degrade any existing figure.
- Regular season only (`reportedGames` is fed to the regular-season profile only for NFL and NBA; playoffs and play-in never use it). NBA behaviour must not change.
- No production writes, no scraper runs, never open or create any `.env*` file, no push, no merge (the controller asks the user).
- Do not touch the database password anywhere; tests use the embedded Postgres only.

- Builds in worktrees need a real `node_modules`; this worktree has a symlink, so run tests, tsc and eslint only (no `next build`).
